# 马尼拉新版港湾版图坐标契约

## 1. 目的与边界

本文件只确认新版地图的固定设计坐标、DOM覆盖区域和缩放分层，暂不改变现有规则、房间同步、放置逻辑或结算逻辑。前端重构时以本文件和 `board-layout.mjs` 为唯一坐标来源，避免在HTML、CSS和JavaScript中重复维护不同数字。

底图：`assets/manila-harbor-board-v1.png`  
设计坐标：`1586 × 992`  
宽高比：约 `16:10`

所有动态文字、投入额、收益、航道等级、船只、助手、货价、骰点和结算结果必须由HTML或Canvas生成，不能写进背景图。

## 3. 三条航道

航道采用中心线而不是矩形格子硬排。等级0位于下方，等级13位于上方：

| 航道 | 0级起点 | 13级终点 |
| --- | --- | --- |
| 左航道 | `(555, 860)` | `(665, 285)` |
| 中航道 | `(755, 860)` | `(785, 285)` |
| 右航道 | `(935, 860)` | `(905, 285)` |

第 `n` 级位置：

```text
t = clamp(n, 0, 13) / 13
x = startX + (endX - startX) × t
y = startY + (endY - startY) × t
```

前端为每条航道生成0～13共14个轻量锚点。锚点只承担数字、悬停说明和当前位置参照；货船本体独立绝对定位到对应坐标，并使用CSS transform或Web Animation沿相邻锚点移动。船只越过13后，不继续堆在航道终点，而进入对应港口或修船厂的结果锚点。

三条船的左右顺序按当轮 `ships` 数组固定，整轮不因货物种类、抵港或玩家视角改变，避免动画横向跳轨。

## 4. DOM与缩放分层

参考 `game22`，但马尼拉需要把随地图缩放的物件演出和不缩放的通知分开：

```html
<section class="harbor-viewport">
  <div class="harbor-world">
    <img class="harbor-background">
    <div class="destination-layer"></div>
    <div class="route-layer"></div>
    <div class="special-layer"></div>
    <div class="market-layer"></div>
    <div class="world-effects"></div>
  </div>
  <section class="dice-stage"></section>
  <div class="viewport-announcement"></div>
  <nav class="map-controls"></nav>
</section>
```

层级建议：

1. 背景图；
2. 静态区域边框和标题；
3. 航道等级与投入/收益信息；
4. 船只、助手和价格标记；
5. 随版图缩放的路线、抵港和结算演出；
6. 不随版图缩放的货物骰控制台与中央播报；
7. 不缩放的地图控制按钮和手势提示。

行动区、倒计时、玩家资产、房间管理、规则、日志与旁观信息均在版图视口之外，不能随地图缩放。

## 5. 交互与移动端

- 初次进入使用 `min(viewportWidth / 1586, viewportHeight / 992)` 完整显示地图；
- 支持按钮缩放、双指捏合、放大后拖动、双击聚焦与一键恢复完整地图；
- 最大比例建议为完整显示比例的4倍；
- 缩放和平移边界沿用 `game22` 的钳制算法；
- 点击放置位与单指拖动必须使用移动阈值区分，短按触发放置，明显移动才进入拖图；
- 地图缩放不能清空尚未提交的港务长配置、领航选择、排序选择或其他本地草稿；
- 手机总览时允许文字简化，但区域高亮、费用、收益和船只当前位置必须可通过放大查看；
- `prefers-reduced-motion` 下取消船只飞行拖尾，仍直接更新到权威位置。

### 港务长货物骰流程

1. 进入掷骰环节时，所有仍在航行的货船各显示一枚对应颜色的货物骰，骰子静止在地图中央；
2. 只有港务长可以点击“开始摇骰”，其他玩家同步看到骰面快速随机变化；
3. 港务长点击“停止骰子”后，房主端一次性生成并保存最终骰点，客户端只播放逐渐减速的骰面演出；
4. 减速结束后才向所有视图公开最终骰点，再按照权威结果移动货船；
5. 待命或运行超过60秒时自动开始或停止，港务长掉线时同样自动推进，避免房间永久卡住；
6. 地图缩放、玩家掉线和其他视图更新不能重新生成最终骰点，也不能重复结算。

## 6. 前端重构验收

- 背景在任何尺寸下都不拉伸变形；
- 七类功能区与底图结构贴合，没有覆盖建筑主体或落入海面错误位置；
- 三条航道均显示0～13，船只位置与服务端 `position` 一致；
- 港口、修船厂、海盗、领航员、保险和货价区都可点击且有明确高亮；
- 船只抵港、进厂、海盗登船和价格上涨具有稳定动画锚点；
- 电脑、平板、手机初始都能看到完整地图，放大后可以平移到所有边缘；
- 地图手势不误触放置，点击棋子区也不会意外拖动画布；
- 骰子与中央通知不因地图缩放而变得过小；
- 现有规则、结算与多人同步行为没有因布局重构发生变化。
